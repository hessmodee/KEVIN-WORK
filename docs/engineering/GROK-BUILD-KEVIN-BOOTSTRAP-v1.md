# Grok Build -> Kevin Bootstrap v1

Status: GREEN bootstrap policy. No production authority expansion.

## Purpose

Grok Build may temporarily accelerate Kevin engineering, but success is measured by how quickly Kevin stops needing it. Grok is a teacher/secondary engineer, not Kevin's permanent nervous system.

## Shared truth

1. Repository: `hessmodee/KEVIN-WORK`.
2. Root `AGENTS.md` is mandatory instruction context.
3. Read `inbox/CURRENT_TASK.md` and `docs/engineering/KEVIN-EXTREME-AUTONOMY-FLYWHEEL-v2.md` before work.
4. Fresh machine/runtime evidence outranks prose or stale HQ presentation.
5. Never claim WORKING, repair, promotion, or owner outcome without the evidence contract for that claim.

## Allowed bootstrap workspace

Grok Build should operate in its own branch/worktree. It may research public sources, inspect repository code, write/refactor code, add deterministic tests, run tests in an isolated worktree/sandbox, prepare reviewed diffs, write diagnosis/lesson/runbook artifacts and propose typed Kevin operations.

Grok must not be given unrestricted production shell merely for speed. It must not widen permissions, expose credentials, change safety policy, silently install system-wide software, send owner-representing communications, purchase/order, trade, or bypass Kevin's typed Engineering/Maintenance/Skill Lab crossings.

## Required handoff for every Grok-assisted repair

Every outside-engineer intervention must leave at least one Kevin-owned dependency-retirement artifact:

- deterministic regression test;
- failure fingerprint + diagnostic recipe;
- typed repair operation/runbook;
- reusable Skill Lab capability;
- watchdog/preflight;
- lesson with exact evidence and rollback contract.

The repair is incomplete if Grok can fix the same failure again but Kevin still cannot recognize or safely route it.

## Work pattern

`REPRODUCE -> COMPETING HYPOTHESES -> LOWEST-IMPACT TEST -> PATCH IN WORKTREE -> POSITIVE/NEGATIVE/REGRESSION TEST -> INDEPENDENT REVIEW -> TYPED CROSSING -> LIVE POSTCONDITION -> BENCHMARK -> LESSON -> RESUME ORIGINAL OWNER WORK`

Grok may build the candidate. Kevin's governed crossing remains the production actuator.

## Good first assignments

1. Reviewer for Supervisor work-supply integration and anti-spin preservation.
2. Reviewer for Maintenance expired-manifest clean-idle semantics.
3. Generate negative/regression fixtures for Incident/Reflection v1.
4. Review isolated OpenClaw Browser/Windows Computer Use qualification harness.
5. Find repeated outside-engineer interventions that should become Kevin skills/runbooks.

## Success metrics

Track weekly:

- `external_engineer_interventions`;
- percentage of repeated failures solved by Kevin without Bess/Grok;
- Grok-assisted fixes that produced a Kevin-owned regression/recipe;
- Kevin-created skills independently reused;
- time from defect detection to verified resume of original work.

Target direction: outside-engineer intervention trends down while verified autonomous owner outcomes and self-repair success trend up.

## Stop rule

If Grok Build becomes the only component capable of understanding or repairing a Kevin subsystem, that subsystem has failed the bootstrap objective. Convert that knowledge into Kevin-readable tests, typed operations and reflection artifacts before adding more features.
